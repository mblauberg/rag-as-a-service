# Python 3.13 Upgrade Design

**Date:** 2025-01-25
**Status:** Approved
**Decision:** Upgrade from Python 3.11 to Python 3.13 (skip 3.14)

## Context

The project currently uses Python 3.11 across all services. We want to stay current with Python versions for long-term maintenance and to benefit from performance improvements and language features.

**Why 3.13 instead of 3.14?**
- Python 3.13 has been stable since October 2024 (over 1 year of maturity)
- Library ecosystem has full support for 3.13
- Python 3.14 just released in October 2025 - too new, ecosystem still catching up
- Some dependencies (FastAPI 0.109) may not fully support 3.14 yet

## Upgrade Strategy

### Single-Phase Upgrade: 3.11 → 3.13

**Timeline:** 1 week

**Changes Required:**

1. **Dockerfiles** (3 Python services):
   - `services/api/Dockerfile`: Change `FROM python:3.11-slim` to `FROM python:3.13-slim`
   - `services/embedder/Dockerfile`: Change `FROM python:3.11-slim` to `FROM python:3.13-slim`
   - `services/generator/Dockerfile`: Change `FROM python:3.11-slim` to `FROM python:3.13-slim`

2. **pyproject.toml files** (3 Python services):
   - `services/api/pyproject.toml`: Change `python = "^3.11"` to `python = "^3.13"`
   - `services/embedder/pyproject.toml`: Change `python = "^3.11"` to `python = "^3.13"`
   - `services/generator/pyproject.toml`: Change `python = "^3.11"` to `python = "^3.13"`

3. **Dependency Updates:**
   - FastAPI: Upgrade from 0.109.0 to latest stable (0.120.x) - adds Python 3.13 support
   - Pydantic: Upgrade from 2.5.3 to 2.12.x for better 3.13 compatibility
   - SQLAlchemy: Already on 2.0.25, fully supports 3.13 (no change needed)
   - PyTorch/sentence-transformers: May need torch upgrade to 2.2.x (verify during testing)

## Implementation Process

### Step 1: Create Feature Branch
```bash
git checkout -b upgrade/python-3.13
```

### Step 2: Update Configuration Files
- Update all 3 Dockerfiles (change base image)
- Update all 3 pyproject.toml files (change Python version constraint)

### Step 3: Regenerate Lock Files
For each service (api, embedder, generator):
```bash
cd services/<service>
poetry lock --no-update  # Regenerate lock file with Python 3.13
poetry update fastapi pydantic  # Get latest compatible versions
```

### Step 4: Rebuild Docker Containers
```bash
docker-compose -f infrastructure/docker-compose/docker-compose.yml down
docker-compose -f infrastructure/docker-compose/docker-compose.yml build
docker-compose -f infrastructure/docker-compose/docker-compose.yml up -d
```

### Step 5: Run Test Suite
```bash
# API tests
cd services/api && poetry run pytest

# Embedder tests
cd services/embedder && poetry run pytest

# Generator tests
cd services/generator && poetry run pytest

# Frontend tests
cd services/frontend && npm test
```

### Step 6: Manual Smoke Testing
1. Upload a document via frontend
2. Search for content
3. Generate a response using RAG
4. Verify all core workflows function correctly

### Step 7: Review and Merge
- If all tests pass, create PR
- Review changes
- Merge to master

## Expected Issues and Mitigations

### Likely Issues:
1. **Poetry lock file conflicts**
   - Mitigation: Run `poetry lock --no-update` in each service

2. **Deprecation warnings for annotation syntax**
   - Mitigation: These are warnings, not errors - can be addressed post-upgrade

3. **Minor dependency version conflicts**
   - Mitigation: Use `poetry update <package>` to resolve

### Unlikely but Possible:
1. **PyTorch/sentence-transformers compatibility issues**
   - Mitigation: Upgrade torch to latest 2.x version

2. **Unstructured library issues** (used in API for document parsing)
   - Mitigation: Check for updates, or pin to current working version

## Rollback Plan

If critical issues arise:
1. Revert the feature branch
2. Stay on Python 3.11 (current stable state)
3. Investigate specific compatibility issues
4. Retry upgrade after resolving blockers

## Success Criteria

- [ ] All Docker containers build successfully
- [ ] All pytest suites pass (api, embedder, generator)
- [ ] Frontend tests pass
- [ ] Manual workflow test completes: upload → search → generate
- [ ] No runtime errors in logs after 24h of operation

## Future Considerations

**Python 3.14 upgrade:**
- Re-evaluate in 3-6 months (mid-2025)
- By then, ecosystem will have matured
- FastAPI, PyTorch, and other dependencies will have stable 3.14 support
- Can use same upgrade process: 3.13 → 3.14
